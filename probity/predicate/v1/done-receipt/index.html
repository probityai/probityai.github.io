Probity

Predicate type: Done Receipt

Type URI:

https://probityai.github.io/probity/predicate/v1/done-receipt

Version 0.1.0. Status: draft, self-hosted predicate type URI.

Purpose

Records the verdict of an outside verifier on one claim: that a coding agent finished its task. The receipt names the records the verdict rests on by digest, carries three checks and the verdict they give, and carries what the agent did outside its workspace. A reader recomputes every one of them from the records, so the receipt asserts nothing a reader cannot check. It is computed over a Done Contract.

The three checks

Claim typeQuestion
protected_paths/v1Did the agent leave the contract's protected paths alone?
acceptance_observed/v1Do the contract's acceptance commands pass when a separate verifier runs them on the agent's final tree?
tool_claim_match/v1Did every command the agent says it ran actually run, after its last edit?

Each returns supported, contradicted or not_established. not_established is an answer, not a failure: the records did not allow either of the others, and the receipt says which record was missing.

Model

The producer is an outside verifier. The subject is the agent's final workspace: one member whose sha256 digest equals tree_sha256 of the tree record. predicateType must equal the type URI above. The records named in records travel beside the receipt, and a reader that does not hold one refuses the receipt rather than trust the carried verdict.

Schema

{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [
    { "name": "workspace-tree", "digest": { "sha256": "<tree_sha256 of the tree record>" } }
  ],
  "predicateType": "https://probityai.github.io/probity/predicate/v1/done-receipt",
  "predicate": {
    "schema_version": "probity-done-receipt/v1",
    "claim_id": "<the records' claim_id>",
    "invocation_id": "<the records' invocation_id>",
    "records": {
      "contract":    { "sha256": "<64-hex>" },
      "tree":        { "sha256": "<64-hex>" },
      "observation": { "sha256": "<64-hex>" },
      "capability":  { "sha256": "<64-hex>" },
      "grade":       { "sha256": "<64-hex>" },
      "claims":      { "sha256": "<64-hex>" },
      "launch":         { "sha256": "<64-hex>" },
      "launch_receipt": { "sha256": "<64-hex>" }
    },
    "checks": [
      { "claim_type": "protected_paths/v1", "decision": "supported",
        "reason": "protected_paths_untouched", "vantage": "independent",
        "witness_scope": "PEER" },
      { "claim_type": "acceptance_observed/v1", "...": "..." },
      { "claim_type": "tool_claim_match/v1", "...": "..." }
    ],
    "verdict": { "decision": "supported", "reason": "done_checks_supported",
                 "vantage": "independent", "witness_scope": "PEER" },
    "external_effects": [],
    "policy": { "table_sha256": "<64-hex>" },
    "stop_decision": { "action": "continue", "reason": "done_checks_supported" },
    "verifier_isolation": { "contract_sha256": "<64-hex>", "...": "..." }
  }
}

checks has exactly three entries in the order above. The optional members are policy, stop_decision, verifier_isolation, and the two launch records, which come together.

The done verdict

  1. If any check is contradicted, the verdict is contradicted with the first such check's reason.
  2. Otherwise, if external_effects holds a mutation at a path a grader loads or writes its result to, the verdict is contradicted with reason external_effect_on_grader_path.
  3. Otherwise, if all three are supported, the verdict is supported with reason done_checks_supported.
  4. Otherwise the verdict is not_established with the reason of the first check that is.

Vantage and witness scope

A supported or contradicted check reports vantage: independent when every record it rests on met its independence pin, and a witness_scope of EXTERNAL only when every such record says EXTERNAL; otherwise PEER. A not_established check reports vantage: unestablished and no scope.
