Predicate type: Agent Change Admission

Type URI:

https://probityai.github.io/probity/predicate/v1/agent-change-admission

Version 1. Status: proposed, self-hosted predicate type URI.

Purpose

An AI agent runs inside a harness: a system prompt, procedures, guards that can block a tool call, and a tool allowlist. This predicate records one decision about one proposed harness change: whether it was admitted, which gates it was checked against, and the digest of every piece of evidence the decision rests on. A rejection is recorded with the same weight as an admission. A relying party uses it to ask: did the evaluator I trust sign an admission of exactly this candidate, against this parent, with every gate I require passed?

Envelope

The decision is signed as a DSSE v1 envelope with Ed25519. A consumer pins its trusted keys out of band; a key carried inside the envelope is never trusted. Two carriages are defined, and the consumer's policy pins which one it reads.

CarriagepayloadTypePayload
bareapplication/vnd.ratchet.decision+jsonthe decision object itself, carrying predicateType
in-totoapplication/vnd.in-toto+jsonan in-toto Statement v1 whose predicate is the decision object and whose subject carries digest.sha256 equal to candidate_digest

Gates

Gate names form a closed set. The consumer's policy pins which it requires.

GateIt passes when
replayevery new guard fires on every target failure at or before the step that caused it and on no passing trace and no benign twin, over the digest-frozen trace snapshot
heldouton fresh held-out runs the candidate beats the better of two fresh parent runs by the required margin, confirmed by a second fresh candidate run
no_regressionno must-succeed case that passed in either parent run fails in a candidate run
benign_twinsthe candidate intervenes on no benign twin
overfit_lintthe candidate's new text carries no identifier, amount or name copied from the training traces
authoritythe tool allowlist is a subset of the parent's, every parent guard and procedure is kept byte for byte, and the parent's system prompt is a prefix of the candidate's, unless a human-signed approval names this exact candidate digest

Verdicts

A verifier returns supported, contradicted or not_established with the reason code of the first check that fails. A decision that passes every step is supported with reason admitted_receipt_verified or rejection_receipt_verified. The full table of thirteen steps is in the specification.

What a valid decision does not establish

A supported verdict means the pinned key signed exactly this decision and every supplied report matches the digest the decision names. It does not establish that the evaluations ran, that the reports are true, or that the key holder is honest.
